# 야구 티켓팅 도우미 v0.9.29

평소 사용하는 Chrome의 NOL 티켓 예매 탭과 연결하는 Windows 도우미입니다. **연결 → 경기 → 좌석 → 시작** 순서로 설정하며 한 번 시작하면 선택한 실행 범위까지 진행합니다. 결제는 Chrome에서 직접 진행합니다.

## 이번 변경

- 좌석 조건 화면은 **한 가지 조건 저장**, 직접 입력하는 **우선순위 구역·블록**, 매수·연석·제외 조건으로 정리했습니다. 시작 화면은 자동 진행 설정과 진단에 집중합니다.
- 자격·인증·할인이 필요한 가격만 있는 좌석 등급은 자동 선택 전에 제외하고 다른 후보를 찾습니다. 설정한 우선순위와 전체 구역 대안 여부를 지킵니다. 매수 부족이나 가격 응답의 구조 오류를 임의로 건너뛰지는 않습니다.
- 여러 구역의 떨어진 좌석을 합칠 때 높은 우선순위 좌석을 유지하며, 부족한 수를 채우는 다음 순위에서도 앞열·통로 선호를 적용합니다.
- **예약 시각 API 진입**은 정상 인증 경로로 준비 화면을 미리 연 뒤, 서버 시각 기준 오픈 −2초부터 +2초까지 30ms 슬롯으로 진입 요청을 시도합니다. 성공 응답을 확인하면 후속 예매 과정으로 넘기고 다른 진행 중 요청과 타이머를 취소합니다. 버튼 활성화를 기다리지 않습니다. 인증·서명은 사이트의 원래 함수가 처리합니다.
- 진입 방식과 −3000~+3000ms 보정값을 변경하면 자동 저장합니다. 고정 ±2초 구간에는 저장한 보정값을 추가 적용하지 않습니다. 앱을 다시 실행해도 유지하며 서버 시각 표본은 매번 새로 확인합니다.

미개방 응답과 일시적인 서버 오류는 구간 안에서 재시도하지만 인증·요청 제한·알 수 없는 결과에는 중지합니다. 원래 사이트 함수가 만든 동일 서명 요청을 재사용하며 서명을 갱신하거나 인증을 우회하지 않습니다. 30ms는 클라이언트 예약 간격으로, OS·브라우저 지연과 서버 도착 시각까지 보장하지 않습니다. 이미 서버가 받은 요청은 취소로 되돌릴 수 없습니다.

2026년 10월 20일 10:16 KST 실행 로그에는 등급 `28`의 가격 **휠체어장애인+동반인 40,000원**, **휠체어장애인 20,000원**이 기록됐습니다. 두 항목 모두 자격·인증 조건으로 제외됐으며 선점은 0건입니다. 이 오류는 `성인`이라는 문구를 찾지 못해서 발생한 것이 아닙니다. 상세 근거는 [가격 선택 기록](docs/handoff-2026-10-19-price-selection.md)에 있습니다.

검증 항목과 결과는 배포본의 **`검증결과.json`**에서 확인하세요. 실제 사용자 브라우저에서 좌석 확보·결제를 완료한 검증은 아닙니다.

## 업데이트하기

1. 기존 도우미에서 **중지**를 누른 뒤 종료합니다. 두 버전을 동시에 실행하지 마세요.
2. **BaseballTicketHelper-v0.9.29.exe**를 실행합니다.
3. **1 연결 → 확장 업데이트 적용 · 다시 연결**을 누른 뒤 예매 탭을 새로고침합니다. 앱과 Chrome 확장을 함께 업데이트해야 합니다.
4. 연결 상태와 대상 경기·좌석 조건을 확인하고 시작합니다. 업데이트나 재연결만으로 중단된 예매를 자동 재개하지 않습니다.

이미 고정 확장 폴더를 등록했다면 다시 등록할 필요가 없습니다. 기존 좌석 조건과 연결을 재사용합니다. 새 실행 파일이 함께 제공된 확장을 고정 위치에 적용하며, 웹에서 새 실행 파일을 자동으로 내려받지는 않습니다.

## 처음 한 번 연결하기

1. 실행 파일을 열고 **1 연결 → 고정 확장 폴더 열기**를 누릅니다.
2. Chrome에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드**에서 1번의 폴더를 선택합니다. 고정 위치는 `%LOCALAPPDATA%\BaseballTicketHelper\chrome-extension`입니다.
4. 도우미의 연결 코드를 복사합니다.
5. Chrome의 확장 프로그램 메뉴에서 **야구 티켓팅 도우미 연결**을 열고 코드를 붙여 넣어 연결합니다.
6. 도우미에 **연결됨**이 표시되는지 확인합니다. 이후 앱·Chrome·확장 재시작 시 저장한 연결로 재연결을 시도합니다.

연결 코드는 같은 PC의 도우미와 Chrome을 연결하는 데 사용하므로 다른 사람에게 공유하지 마세요. **새 연결 코드 만들기**는 기존 연결을 폐기합니다. 최초 확장 등록과 Chrome의 권한 확인은 직접 진행해야 합니다.

창이 보이지 않으면 실행 파일을 다시 열거나 작업 표시줄의 야구공 트레이 아이콘을 누릅니다. 창 위치 복구와 **다른 창 위에 도우미 표시**를 사용할 수 있습니다. 창의 X를 누르면 도우미와 자동 진행이 종료됩니다.

## 예매 준비와 실행

1. **2 경기**에서 **포스트시즌 공식 페이지 열기**를 누르고 Chrome에서 로그인합니다. 다른 경기 주소·두산 테스트·가상 좌석 연습은 추가 메뉴에서 열 수 있습니다.
2. **도움을 받을 Chrome 탭**을 확인하고 **경기 목록 읽기**로 대상 경기를 선택합니다. 판매 시작 시각과 경기 시작 시각은 다릅니다. 읽지 못한 일정은 추측하지 않습니다.
3. **3 좌석**에서 1~4매, 연석 여부, 시야방해석 제외, 장애인·휠체어석 포함 여부와 우선순위를 정합니다. 다음 실행에도 사용할 조건은 **좌석 조건 저장**을 누릅니다. 실행에는 현재 입력값을 사용합니다.
4. **4 시작**에서 실행 범위를 선택하고 **자동 진행 시작**을 누릅니다. 기본 흐름은 목록 → 준비 화면 → 대기열 → 안내·보안문자 → 좌석·일반 가격 선택 → 다음 화면 확인입니다.
5. 필요한 경우 **중지**를 누릅니다. 결제는 직접 진행합니다.

실행 범위는 **좌석·일반 가격 선택 후 예매하기까지**, **좌석 선택까지만**, **예매창 진입까지만**, **보안문자 후 정보 기록·정지** 중에서 고릅니다. 예매창 진입까지만 선택하면 도착 이후 안내·보안문자·좌석 처리를 시작하지 않습니다.

이미 열린 좌석 화면에서도 시작할 수 있습니다. 이때 새 진입 요청이나 시각 예약을 만들지 않고 현재 화면부터 처리합니다. 이미 선택한 좌석·가격 또는 결과가 불확실한 이전 요청은 덮어쓰지 않습니다. 가격 화면 재개는 현재 선택과 매수의 검증을 통과해야 합니다.

**실행 전 점검**은 연결·설정·현재 화면을 읽어 진행 가능 여부를 확인합니다. 점검 성공이 로그인·입장 권한이나 좌석 확보를 보장하지는 않습니다. **가상 좌석 연습**은 실제 선점·결제와 관계없는 로컬 연습 화면입니다.

## 우선순위 구역·블록

구역 이름 또는 코드와 블록을 직접 입력합니다. 이름·코드는 정확히 일치해야 하며 띄어쓰기는 무시합니다. 코드 `1`과 `10`은 다르고, 전체 블록 코드 `001:1`과 `002:1`도 구별합니다. 블록 이름 `1`만 입력하면 그 이름이 일치하는 블록을 허용합니다.

- **조건 묶음**은 위에서부터 적용합니다. 순서를 바꾸면 우선순위도 바뀝니다. 같은 묶음의 여러 구역·블록은 동등한 허용 범위입니다.
- 조건 묶음을 모두 끄면 **기본 우선 구역·블록**을 적용합니다. 입력 목록의 나열 순서를 별도 순위로 해석하지 않습니다. 순서를 지정하려면 조건 묶음을 나누세요.
- 빈 구역·블록·열은 해당 제한이 없다는 뜻입니다. 숫자 열 범위는 양 끝을 포함합니다. 확인된 문자 열 A~Z는 A=1부터 Z=26까지 입력합니다. AA·A1 같은 미확인 표기는 추정하지 않습니다.
- **우선순위에 자리가 없으면 전체 구역에서 찾기**를 켜면 마지막에 구역·블록·열 제한을 풉니다. 매수·연석·시야방해석·장애인석 설정은 유지합니다. 끄면 설정한 범위만 확인합니다. 우선순위를 비워 두면 처음부터 전체 구역을 찾습니다.
- 기본 선호는 구역명에서 확인되는 **3루·중앙 → 필드/그라운드/익사이팅/덕아웃, 내야 표기 → 앞열 → 통로 거리**입니다. 숫자 블록이나 가격으로 실제 경기장 거리를 추정하지 않습니다.

**반드시 나란히 앉기 · 연석**을 켜면 같은 물리적 행의 인접 관계가 확인된 조합만 사용합니다. 끄면 서로 다른 구역·등급·블록을 합쳐 매수를 채웁니다. 1순위 1석, 2순위 2석이 있고 2매를 요청하면 1순위 1석과 2순위 1석을 먼저 선택합니다.

통로는 좌석 배열로 추정하므로 벽 쪽 끝자리와 다를 수 있습니다. 시야방해석은 확인된 사이트 표시를 기준으로 제외하며 미확인 좌석을 정상 시야로 가정하지 않습니다. `104블록 W4-1` 같은 특수 표기의 검증된 1인 휠체어석은 **1매·포함 옵션 켜짐·숫자 열 제한 없음**일 때만 지원합니다. 여러 명이 묶인 좌석은 지원하지 않습니다. 포함 옵션은 이용 자격이나 가격 인증을 생략하지 않습니다.

## 일반 가격 선택과 실패 처리

선택할 좌석의 등급별 매수를 합산하고 사이트 가격 목록의 원래 순서대로 첫 적격 일반 가격을 선택합니다. `성인`이라는 특정 문구를 요구하지 않으며 최저가 순으로 재정렬하지 않습니다. 회원·인증·카드·쿠폰·할인·별도 자격 조건, 금액과 매수 제한을 함께 확인합니다.

자동으로 새 좌석을 찾는 중이고 아직 선점하지 않았다면, 자격·인증·할인 가격만 제공되는 등급을 해당 탐색 회차에서 제외하고 다른 후보를 찾습니다. 다음 회차에는 다시 확인합니다. 매수 조건만 맞지 않거나 응답 형식·등급 연결이 불명확한 경우, 이미 선택한 좌석이나 가격을 이어가는 경우에는 이 방식으로 건너뛰지 않고 중지합니다.

모든 후보 블록의 최신 상세 정보와 잔여 상태를 선점 직전에 확인합니다. 명시적인 좌석 충돌은 도우미가 확보한 좌석의 해제 결과까지 확인한 뒤 다음 후보로 넘어갑니다. 시간 초과·세션 변경·연결 끊김·알 수 없는 응답은 결과를 추측해 재전송하지 않습니다.

조건에 맞는 좌석이 없으면 다시 높은 순위부터 탐색합니다. 전체 구역 확인 후 다음 회차는 3~5초 이내에 재개하며, 의미 있는 좌석 정보 변경이 오면 대기를 끝냅니다. 상세 정보가 부족한 구역만 남으면 1초 후 재확인합니다. 화면에 갱신 수단이 없는 지도는 실제 정보 변화를 기다립니다. 이 간격은 좌석 탐색용이며 예매 버튼 활성화 감지에 추가하지 않습니다.

실행 중에는 대상·조건 변경을 잠급니다. **중지**는 이미 서버로 보낸 요청을 취소하지 못하므로 결과가 불확실하면 현재 사이트 상태를 직접 확인해야 합니다. 실제 예매 동작은 HTTP 또는 사이트 함수로 처리하며 마우스 입력으로 대체하지 않습니다.

## 서버 시계와 진입 방식

| 표시·방식 | 의미 |
|---|---|
| 사이트에 공지된 예매 시작 | 해당 경기의 티켓 판매 시작 일정. 한국 시각으로 표시합니다. |
| 서버 시계와 내 PC의 차이 | 측정 당시 서버 시각과 PC 시각의 차이 및 통신에 따른 추정 오차입니다. PC 시계를 변경하지 않습니다. |
| 활성화 감지 · 요청 중복 방지 | 서버 시각 조회 없이 실제 예매 버튼 활성화를 확인해 진입합니다. |
| 예약 시각 API 진입 | 준비 화면을 미리 열고, 유효한 서버 시각으로 계산한 시각에 진입 API를 한 번 호출합니다. 버튼 활성화는 조건으로 사용하지 않습니다. |

예약 방식은 서버 시각을 다시 읽어 보정하며 시각 정보가 만료되면 최근 표본을 기다립니다. 일반 웹 응답 시각은 대체 표시할 수 있지만 예약 실행에는 사용하지 않습니다. PC 시계가 바뀌어도 이미 연결한 예약은 단조 시계를 기준으로 유지합니다.

**진입 시각 보정(ms)**은 공지된 오픈 시각에 −250~+250ms를 더합니다. 기본값은 0입니다. 음수는 앞당기고 양수는 늦춥니다. 진입 방식과 보정값은 자동 저장됩니다. 서버가 아직 개방하지 않았다면 요청이 거절될 수 있으며, 거절 응답을 자동 재전송하지 않습니다.

예약 방식은 공식 경기·장소·판매 시작 시각을 확인하고 정상 SSO → 준비 화면 경로를 사용합니다. 준비 화면의 현재 사이트 함수 계약을 확인하지 못하거나 로그인·인증·시각 문제가 있으면 중지합니다. 활성화 감지 방식으로 자동 변경하지 않습니다. 사이트가 스스로 시작한 진입 요청도 같은 시각·중복 제한을 적용합니다.

예약 방식에서는 사이트 진입 함수를 실행당 한 번 호출합니다. 활성화 감지 방식만 요청 없이 끝난 함수를 1초 뒤 최대 3회 확인합니다. 요청이 나갔다면 응답이 늦어도 추가 전송하지 않고 최대 30초 확인합니다. 미개방·제한·결과 불명은 기록 후 중지합니다. 자세한 계약과 검증 범위는 [진입 방식 문서](docs/entry-strategy-2026-10-18.md)를 참고하세요.

새 팝업으로 이어갈 때 기존 목록 감시 중지를 확인합니다. 화면 전환 중 사라진 읽기 응답은 실제 문서 이동을 확인해 이어가며 진입·선택 동작을 재실행하지 않습니다. Chrome 최소화·가림 상태에서도 처리하지만 PC 절전, 탭 동결·폐기, 연결 해제로 중단될 수 있습니다. 정확한 밀리초 실행이나 혼잡한 실사이트의 순번 개선은 보장하지 않습니다.

## 안내와 보안문자

확인된 **예매 안내·취소/환불 안내**의 **확인하고 예매하기**를 각각 한 번 처리합니다. 없는 안내를 기다리지 않으며 내용이 같은 안내가 닫히지 않아도 중복 실행하지 않습니다. 알 수 없는 동의·결제·인증 단계를 이 기능으로 넘기지 않습니다. 자동 확인은 시작 화면의 **진단 도구 → 자동 확인 설정**에서 조절합니다.

일반 자동 진행에서는 보안문자 인식·입력·확인을 사용합니다. 독립적으로 확인하려면 **보안문자만 따로 테스트하기**에서 읽기만 하거나 입력·확인까지 실행할 수 있습니다. 직접 입력 보조에서는 현재 이미지를 확인하고 영문 6자리를 작성한 뒤 Enter 또는 **입력·확인**으로 제출합니다. 사용자가 이미 작성한 내용은 덮어쓰지 않습니다.

문자 이미지 지원 범위는 확인된 원스톱 예매창과 구형 `Book/`, `SportsBook/`입니다. 다른 인증 방식은 사이트에서 직접 처리합니다. 버튼 실행이나 문자 제출 자체를 인증 성공으로 판단하지 않습니다.

## 로그·설정과 지원 범위

- 설정: `%LOCALAPPDATA%\BaseballTicketHelper\settings`. 좌석 조건은 `preferences.json`, 창·페이지·진입 방식·보정값은 `settings.json`에 저장합니다.
- 실행 로그: 위 폴더의 `logs`. 최근 30개 실행을 보관하며 실행당 최대 1MiB입니다. 마지막 정제 결과는 `last-run.json`에서 다시 읽습니다.
- `price-selection`에는 등급·매수·가격명·금액·목록 순서·선택·제외 사유를 기록합니다. 등급 8개·등급당 30개 항목으로 제한하고 선택 항목을 보존합니다. 자격 가격뿐인 등급을 건너뛰면 `seat-price-unavailable`을 기록합니다.
- 단계·안내·좌석 정보 부족·진입 요청 및 응답을 구분해 기록합니다. `requestDeadlineDelayMs`는 예약 시각 대비 실제 요청 전송 지연이며 서버 접수 시각은 아닙니다. 보안문자 이미지·인식값·쿠키·인증 토큰·응답 본문은 실행 로그에 저장하지 않습니다. 명령 시간은 통신·대기를 포함하며 겹치는 시간을 합산해 전체 실행 시간으로 해석하지 않습니다.
- 개발 실행의 설정은 `work/desktop-settings`를 사용합니다. GitHub에는 소스·테스트·문서만 올리고 사용자 설정·실행 로그·인증 자료는 올리지 않습니다.

Chrome 로그인 정보는 Chrome이 관리합니다. 앱과 확장은 같은 PC의 로컬 연결을 사용합니다. 앱의 연결 자격은 Windows 암호화 저장소로 암호화하며 확장은 신뢰된 확장 문맥의 로컬 저장소를 사용합니다. Chrome의 디버깅 안내에서 연결을 해제하거나 개발자 도구 등과 충돌하면 관찰·자동 진행이 중지될 수 있습니다.

현재 확인된 NOL 경기 목록·준비 화면·원스톱 좌석 구조가 대상입니다. 모든 종목·구장의 실시간 좌석 구조를 지원한다고 보장하지 않습니다. 공식 좌석 안내 이미지는 배치 참고자료이며 잔여석·통로·연석 확정 데이터가 아닙니다. 공개 일정·정책은 마지막으로 읽은 시점 기준이고 과거 공지로 새 경기의 일정을 추정하지 않습니다.

## 개발과 검증

- `npm start`: Chrome 연결 패널 실행
- `npm test`: 좌석·가격·취소·복구·시각·연결 단위 검사
- `npm run package`: Windows 배포 폴더 생성

단위 검사, 설정 화면 검사, 격리 Chromium의 목록→준비→좌석→가격→다음 화면 흐름과 중지·재시작을 검증합니다. 실제 계정에서의 선점·결제 결과와 구분하며 각 배포본의 `검증결과.json`에 수행 결과를 남깁니다.
