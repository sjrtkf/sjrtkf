# 야구 티켓팅 도우미 v0.9.5

## 작업 중단 시점 · 2026-10-15

사용자 요청으로 기능 개발과 실제 예매 테스트를 중단했습니다. 이 저장소는 **v0.9.5 작업 체크포인트**이며 실제 좌석 확보까지 검증한 완성본이 아닙니다.

- 완료된 변경: 예매 안내·취소/환불 안내의 `확인하고 예매하기` 버튼 처리, 두 안내가 연속으로 나타나는 경우 각각 한 번 처리, 정상 예매창 전환 도중 읽기 요청이 실패해 자동 진행이 중단되는 문제 수정. 일반 경로에 추가 대기를 넣지 않았습니다.
- 마지막 로컬 검증 기록: 단위 테스트 404개 통과, 패널 점검 66개 통과, 소스·배포 파일 62개 비교 및 OCR 배포 파일 4개 일치. 기록 시각은 2026-10-15 17:39 KST이며 이번 Git 정리에서 실제 예매 테스트를 다시 실행하지 않았습니다. 네이티브 창의 항상 위 표시 여부는 미확인입니다.
- 실제 확인: 강원FC–프놈펜 크라운FC, 2026-10-15 19:00 강릉종합운동장 경기에서 v0.9.5 도우미로 새로 진입한 뒤 좌석 지도까지 이동했습니다. 표시 좌석 후보는 있었지만 상세 정보가 부족해 조건에 맞는 조합은 0개였습니다. 이후 `구역 목록으로 돌아가는 화면 전환을 확인하지 못했습니다.`로 중단했습니다.
- 미완료: 실제 좌석 선택, 선택 완료 후 가격/할인 화면 진입, 실제 오픈 순간 속도 비교. 결제는 수행하지 않았습니다. 광주·잠실·라이온즈파크의 실제 좌석 선택도 검증하지 않았습니다.

다음 작업자는 아래 두 문제부터 확인하세요. **아직 수정하지 않았습니다.**

1. `src/metadata.js`의 `metadataUrl()`은 `/onestop/api/seatMeta`만 읽습니다. 공개 사이트 코드에 별도 `/onestop/api/externalSeatMeta` 경로가 있지만, 강원 경기에서 실제로 그 응답을 사용했는지는 확인 전입니다. 실제 요청과 응답 형식을 확인한 뒤 상세 정보 누락 원인을 판단해야 합니다.
2. `src/chrome-main.js`의 `nextGrade()`는 `좌석도 전체보기`를 구역 목록으로 복귀하는 버튼으로 취급합니다. 실제 화면에서는 `ZoomControls_zoomFitButton`인 지도 확대/축소 맞춤 버튼으로 확인했습니다. 올바른 구역 전환 경로를 확인해야 합니다.

좌석 선택 뒤 표시되는 열·블록 표기와 `src/selection.js`의 검증 문자열 일치 여부, 실제 지도에서 클릭 이벤트가 좌석을 선택하는지도 후속 검증 대상입니다. 상세 정보가 없을 때 조건 검증을 생략하여 진행하지 마세요. 보안문자 코드·모델은 이번 체크포인트 정리에서 변경하거나 재학습하지 않았습니다.

당시 포스트시즌 조사에서는 [NOL 포스트시즌 페이지](https://nol.yanolja.com/ticket/genre/sports/postseason)의 광주·잠실 좌석 안내와 광주 경기 카드 3개를 확인했습니다. NOL의 삼성 경기 카드는 확인하지 못했고, [삼성 구단 공식 좌석 안내](https://www.samsunglions.com/score/score_4_2_1.asp)는 별도 참고자료입니다. 이 내용은 조사 당시 기록이며 새로운 일정·재고를 보장하지 않습니다.

## 다른 PC에서 이어서 개발하기

Windows, Git, Node.js 22.12 이상 호환 버전과 Chrome을 준비합니다. Node.js 하한은 현재 잠금 파일의 패키지 요구사항입니다. 저장소는 [sjrtkf/sjrtkf](https://github.com/sjrtkf/sjrtkf)이며 기본 브랜치는 `main`입니다.

```powershell
git clone https://github.com/sjrtkf/sjrtkf.git baseball-ticket-helper
cd baseball-ticket-helper
npm ci
npm test
npm start
```

인터넷 없이 소스 기록을 옮길 때는 별도로 만든 `baseball-ticket-helper-v0.9.5-checkpoint.bundle`을 복사한 뒤 `git clone .\baseball-ticket-helper-v0.9.5-checkpoint.bundle baseball-ticket-helper`로 복제할 수 있습니다. bundle은 생성 당시의 기록만 포함합니다. 이후 원격으로 동기화하려면 `git remote set-url origin https://github.com/sjrtkf/sjrtkf.git`로 주소를 설정하세요.

`npm start`는 확장 생성 파일을 갱신한 뒤 설정 패널을 실행합니다. 새 PC의 Chrome에서 `chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램 로드 → 이 소스 폴더의 **`extension` 폴더**를 선택합니다. 도우미의 새 연결 코드로 연결하고, 사이트 로그인은 새 PC에서 직접 진행합니다. 이전 PC의 연결 코드는 재사용하지 않습니다.

Git에는 소스·테스트·잠금 파일·기존 모델 파일이 포함됩니다. `node_modules`, `outputs`, `work`, Python 캐시, `.env`는 제외합니다. 따라서 배포 실행 파일, 개발 실행의 개인 설정, 학습용 원본 이미지, 로컬 로그·검증 기록은 복제되지 않습니다. 코드만 받아 실행하면 별도 OCR 실행 파일은 없을 수 있습니다. 기존 Windows 배포본을 그대로 쓰려면 **`outputs/BaseballTicketHelper-v0.9.5-win32-x64` 폴더 전체**를 별도로 복사하고, 그 안의 **`chrome-extension` 폴더**를 Chrome에 등록하세요. `.exe` 하나만 옮기면 안 됩니다.

현재 `npm run package`는 사전에 만들어진 `outputs/CaptchaWorker-v0.1` 폴더를 요구하므로 소스 복제와 `npm ci`만으로 배포 재생성이 끝나지는 않습니다. 기존 배포본을 이용하는 경우 다시 빌드할 필요는 없습니다. 로그인 쿠키·브라우저 프로필·연결 토큰은 다른 PC로 복사하지 마세요. 사용 중인 배포본의 좌석 선호 설정은 실행 파일 옆 `settings`에 있고 개발 실행 설정은 `work/desktop-settings`에 있습니다.

새 작업 환경에서는 이 README의 작업 중단 시점을 먼저 읽고 현재 Git 커밋을 확인하면 됩니다. Git은 코드와 문서만 옮기며, 이 대화의 전체 기록이나 로그인된 Chrome 상태까지 옮기지는 않습니다.

## 프로그램 안내

**왼쪽의 작은 Windows 프로그램에서 조건을 정하고, 평소 사용하는 Chrome에서 예매합니다.** Chrome의 로그인 상태와 예매 화면을 그대로 사용하며 프로그램 안에 웹사이트를 띄우지 않습니다.

삼성 라이온즈를 응원하는 사용자의 포스트시즌 예매 준비를 목표로 합니다. 기본 페이지는 [NOL 포스트시즌](https://nol.yanolja.com/ticket/genre/sports/postseason)이며 두산 페이지는 테스트 대상으로 제공합니다. 삼성 응원 구역·홈/원정 방향은 구장과 경기마다 다르므로 자동으로 고정하지 않습니다. 현재 페이지에 공개되지 않은 경기의 판매 일정과 좌석 구조는 추정하지 않습니다.

실행 파일: `outputs/BaseballTicketHelper-v0.9.5-win32-x64/BaseballTicketHelper-v0.9.5.exe`

다른 PC로 옮길 때는 실행 파일과 `chrome-extension`이 들어 있는 배포 폴더 전체를 복사합니다. 이전 배포본은 별도로 남습니다. v0.9.5를 같은 outputs 폴더에서 처음 실행하면 인접한 v0.9.4부터 이전 버전 순서로 좌석 선호·일반 설정과 구장별 조건을 새 설정이 없는 항목에 한해 가져옵니다. 이전 설정은 덮어쓰지 않고 로그인 정보·쿠키·토큰은 복사하지 않습니다.

v0.9.5는 **취소/환불 안내 및 연속 안내 처리, 정상 예매창 전환 중단 오류**를 수정합니다. 제목이 예매 안내 또는 취소/환불 안내인 팝업의 정확한 확인하고 예매하기 버튼을 각각 한 번 누릅니다. 예매 준비 화면을 읽는 도중 문서가 바뀌면 새 화면 전환을 확인하고 이어가며, 이미 전달한 진입·좌석·완료 동작은 다시 보내지 않습니다. 정상 경로에 대기를 추가하지 않았습니다.

v0.9.4는 **실행 전 점검·중지 원인·단계별 시간 분석·열린 좌석 화면에서 시작**을 추가합니다. 시작 탭의 실행 전 점검은 확장 연결과 사이트 응답 관찰을 따로 확인하고, 현재 지도에서 상세 정보와 조건에 맞는 조합 수를 알려줍니다. 점검은 좌석을 선택하지 않습니다. 점검 성공은 로그인·입장 권한이나 좌석 확보를 보장하지 않습니다.

이미 열린 원스톱 좌석 탭을 선택하면 **현재 좌석 화면에서 시작**을 누를 수 있습니다. 새 진입 요청은 보내지 않으며, 이미 선택된 좌석이 있으면 중지해 확인을 안내합니다. 연결만으로 자동 재개하지 않습니다. 연결 전에 지도를 열어 상세 정보가 없다면 구역 목록에서 다시 들어가세요.

단일 대문자 A~Z 열을 지원합니다. 원래 문자 표기를 화면에 유지하며 열 범위 설정에는 A=1, B=2, …, Z=26을 사용합니다. AA·A1 등 확인되지 않은 표기는 추정하지 않습니다. 연석은 여전히 같은 물리적 행·인접 정보로 검증합니다. 구역과 직접 선택 화면의 정상 전환 뒤 불필요한 고정 대기를 없앴고, 전환 중 같은 버튼을 반복해서 누르지 않습니다.

마지막 작업에서 중지 이유·다음 행동과 단계별 체류 시간, 명령 처리 시간을 확인할 수 있습니다. 단계 시간에는 사용자 입력·서버 대기가 포함되고, 동시에 실행된 명령의 누적 시간은 겹칠 수 있어 전체 경과 시간과 더하거나 직접 비교하지 않습니다. 보안문자 모델과 인식 코드는 이번 버전에서 변경하지 않았습니다.

v0.9.3은 **사람이 직접 입력하는 과정**을 개선합니다. 보안문자가 나타나면 도우미의 확대 이미지와 입력칸을 보여주며, Chrome 입력칸에는 처음 한 번만 포커스를 준비합니다. 다른 곳에서 작성 중인 내용은 방해하지 않습니다. 도우미에 영문 6자리를 직접 작성한 뒤 Enter 또는 입력·확인을 누르면 한 번 전달합니다. 6글자를 채우는 것만으로 제출하지 않습니다.

직접 입력 보조는 기본으로 켜져 있고 기존 설정을 가져와도 우선 적용합니다. 같은 이미지의 반복 상태 갱신은 작성 중인 글자와 포커스를 유지합니다. 이미지·문서·탭이 바뀌면 이전 입력을 무효화하며, 사이트에서 직접 작성한 글자는 덮어쓰지 않습니다. 제출 경로에 인위적인 시간 지연이나 자동 정답 생성은 없습니다. 사이트 응답과 통신에 걸리는 시간은 그대로 필요합니다.

이번 버전에서는 모델 재학습·전체 이미지 학습·인식 정확도 개선을 수행하지 않았습니다. 기존 모델 파일은 변경하지 않았습니다. 직접 입력 기능은 인식 모델을 호출하지 않습니다. 로컬 합성 화면으로 검증하며 실제 사이트 동작은 사용자가 확인해야 합니다.

## 이전 버전에서 업데이트하기

1. 이전 도우미에서 **중지** 후 종료하고 **BaseballTicketHelper-v0.9.5.exe**를 실행합니다. 두 버전을 동시에 실행하면 연결을 사용할 수 없다는 안내가 나올 수 있습니다.
2. 문자 열과 연결 해제 원인 지원에는 **0.9.5 확장**을 사용하세요. Chrome의 `chrome://extensions`에서 이전 확장을 사용 중지하고, **압축해제된 확장 프로그램을 로드**로 새 배포 폴더의 `chrome-extension`을 등록합니다. 이전 폴더의 새로고침만으로는 새 기능이 추가되지 않습니다.
3. 도우미의 **1 연결**에서 새 코드를 복사해 확장에 다시 연결합니다. 상단 v0.9.5 표시 → 대상 경기·구장 설정 → **4 시작 → 실행 전 점검** 순서로 확인합니다. 좌석까지 시험할 때는 **진입 확인만**을 끄고 **선택 완료까지 진행**을 켜세요. 개발자 도구나 다른 브라우저 제어가 관찰 연결과 충돌할 수 있습니다.

설정 화면은 **1 연결 → 2 경기 → 3 좌석 → 4 시작** 순서이며, **5 보안문자**에서 경기 선택 없이 직접 입력 기능을 따로 시험할 수 있습니다. 상단에는 다음 할 일, 하단에는 진행 상태·시작·중지가 계속 표시됩니다. 좌석 조건 변경 시 미저장 표시가 나오며, 실행에는 현재 입력값을 사용하고 다음 실행에도 남기려면 저장합니다.

창이 보이지 않으면 실행 파일을 다시 열거나 작업 표시줄 오른쪽의 야구공 트레이 아이콘을 누르세요. 트레이 메뉴의 **창 위치를 왼쪽으로 복구**로 모니터 밖에 있는 창도 되돌릴 수 있습니다. 연결 단계의 **다른 창 위에 도우미 표시**는 켜고 끌 수 있습니다. X를 누르면 프로그램과 자동 보조가 종료됩니다.

## 처음 한 번 연결하기

1. **BaseballTicketHelper-v0.9.5.exe**를 실행합니다. 작은 설정 창이 화면 왼쪽에 뜹니다. 창 위치와 항상 위 표시 설정은 저장되며, Chrome 창을 옆에 두면 나란히 볼 수 있습니다.
2. 프로그램의 **Chrome 확장 프로그램 폴더 열기**를 누릅니다. 배포 폴더 안의 `chrome-extension` 폴더가 열립니다.
3. 평소 사용하는 Chrome에서 주소창에 `chrome://extensions`를 입력합니다.
4. **개발자 모드**를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 누른 뒤, 2번의 `chrome-extension` 폴더를 선택합니다. 이 배포본은 Chrome 웹 스토어 설치본이 아닙니다.
5. Chrome 도구 모음의 확장 프로그램 메뉴에서 **야구 티켓팅 도우미 연결**을 엽니다. 자주 쓰려면 고정해 둡니다.
6. Windows 프로그램에서 **연결 코드 → 복사**를 누른 뒤 Chrome 확장의 입력칸에 붙여 넣고 연결합니다. 코드가 만료됐다면 **새 연결 코드 만들기**를 누릅니다.
7. Windows 프로그램에 **연결됨**이 표시되면 준비 완료입니다. 프로그램을 새로 실행했을 때 연결 전이라면 새 코드로 다시 연결합니다.

연결 코드는 같은 PC의 프로그램과 Chrome을 연결하는 데 쓰며 다른 사람에게 공유하지 않습니다. 처음 설치하는 과정과 Chrome의 권한 확인은 사용자가 직접 진행합니다. 앱을 종료하면 자동 보조도 종료됩니다.

좌석 정보와 처리 결과를 확인할 때 Chrome 상단에 확장이 디버깅을 시작했다는 안내가 보일 수 있습니다. 이 연결을 해제하거나 개발자 도구와 충돌하여 관찰이 중단되면 자동 진행도 중지될 수 있습니다. Chrome의 기존 로그인 정보는 계속 Chrome에 남습니다.

## 예매 준비 순서

1. **2 경기**에서 **포스트시즌 공식 페이지 열기**를 누릅니다. 다른 주소는 **다른 경기 주소 · 테스트 페이지**에서 입력할 수 있고, 가상 좌석 연습과 두산 테스트도 이곳에 있습니다.
2. Chrome에서 로그인합니다. 프로그램의 **도움을 받을 Chrome 탭**에서 대상 탭을 확인합니다.
3. **경기 목록 읽기**를 눌러 경기를 선택합니다. 페이지 제목·조회 시각·확인한 정책과 공식 좌석 안내 링크도 표시합니다. 사이트의 **판매 상품 없음**과 **카드 구조를 읽지 못함**은 구분하여 안내합니다. 다른 경기 구조라 목록을 읽지 못하는 경우 해당 페이지에서 수동으로 준비 화면까지 이동하고 대상 탭을 선택합니다.
4. **3 좌석**에서 구장 설정을 먼저 고릅니다. 라이온즈파크·광주·잠실·강원 FC 테스트의 조건을 각각 저장할 수 있습니다. 좌석 수(1~4매), 연석 여부, 시야방해석 제외, 순위별 구역·블록·열·통로 조건을 예매 전에 입력하세요. 다른 구장으로 전환하면 현재 조건을 이전 구장에 저장하고 선택한 구장의 조건을 불러옵니다.
5. **4 시작**에서 경기·좌석 조건을 확인한 뒤 **자동 진행 시작**을 누릅니다. 정상 경기 카드를 통해 준비 화면으로 미리 들어가 버튼이 활성화되면 한 번 클릭합니다. 서버 시계와 시험 진입 방식은 고급 설정에 있습니다. Chrome 예매 탭은 화면에 보이는 상태로 유지하세요. 사이트 자체의 시각 업데이트가 숨겨진 탭에서 느려지거나 멈출 수 있습니다.
6. **보안문자 직접 입력 보조**가 기본으로 켜져 있습니다. 지원 화면이 나타나면 확대 이미지를 표시하고 직접 입력을 기다립니다. Chrome에서 그대로 입력하거나 도우미의 직접 입력칸에 작성하고 Enter로 확인합니다. 사이트에서 보안문자 창이 사라진 뒤 기존 진행이 이어집니다.
7. 설정한 조건으로 좌석 후보를 찾고 선택 완료를 누른 뒤 실제 가격/할인 단계로 이동했는지 확인합니다. 가격·할인·주문·결제는 Chrome에서 직접 진행합니다.

**가상 좌석 연습**은 Chrome 확장의 로컬 연습 화면을 엽니다. 실제 좌석 선점이나 결제와 관계없이 조건 설정과 선택 흐름을 확인하는 용도입니다.

## 선택적으로 나타나는 예매 안내

준비 화면과 좌석 화면에서 **예매 안내·취소/환불 안내**의 정확한 **확인하고 예매하기** 버튼을 확인해 한 번 누릅니다. 이 안내가 없으면 별도로 기다리지 않고 기존 단계를 진행합니다. 두 종류의 안내가 연속으로 나타나면 각각 한 번 처리합니다. 확인되지 않은 제목이나 결제·인증·동의 단계는 자동으로 넘기지 않습니다. 같은 안내가 닫히지 않아도 중복 클릭하지 않으며, 로그인·보안문자·동의 입력창은 이 기능으로 처리하지 않습니다. **3 좌석 → 자동 진행 범위 → 예매 안내 확인 자동 클릭**을 끄면 사용자가 직접 누르도록 기다립니다.

진입 확인만 모드는 준비 화면의 진입을 가로막는 일반 안내는 통과하지만, 원스톱 예매창 경로에 도착하면 멈춥니다. 도착 이후 안내·보안문자·좌석 동작은 일반 진행 모드의 범위입니다.

## 보안문자를 따로 시험하기

경기 목록을 읽거나 자동 진행을 시작할 필요가 없습니다. Chrome에서 콘서트 예매창을 열어 보안문자가 보이게 한 뒤, **5 보안문자**에서 그 예매창을 선택합니다.

1. **이미지 보기·입력 준비**를 누르면 현재 이미지를 확대 표시합니다. 이 단계에서는 글자를 입력하거나 확인 버튼을 누르지 않습니다.
2. 이미지의 영문 6자리를 직접 작성합니다. 소문자는 대문자로 표시합니다. **Enter** 또는 **입력·확인**으로 한 번 전달합니다.
3. Chrome에서 이미 작성 중이면 도우미가 덮어쓰지 않습니다. **Chrome 입력칸 보기**로 돌아가 확인하세요.
4. 새 이미지가 나왔거나 탭을 바꿨다면 **이미지 보기·입력 준비**를 다시 눌러 주세요. 자동 진행 중에는 현재 보안문자 화면의 변화를 확인해 표시합니다.

지원 대상은 원스톱 예매창(`tickets.interpark.com/onestop/`)과 구형 예매창(`ticket.interpark.com/Book/`, `SportsBook/`)의 문자 이미지입니다. 다른 인증 방식은 사이트에서 직접 진행합니다. 사이트가 확인 버튼을 활성화하지 않거나 입력 화면 구조가 달라지면 상태에 이유를 표시합니다. 버튼 전달은 인증 성공을 의미하지 않습니다. 실제 결과는 Chrome에서 확인하세요.

## 시각 표시를 읽는 방법

두 표시는 서로 다른 정보입니다.

| 표시 | 뜻 | 예시 |
|---|---|---|
| 사이트에 공지된 예매 시작 | 해당 경기의 티켓 판매가 시작될 예정 시각. 경기 시작 시각과 다릅니다. | 9월 20일 오전 11시 |
| 서버 시계와 내 PC의 차이 | 사이트에서 읽은 현재 시계가 내 PC보다 얼마나 빠르거나 느린지에 대한 추정 | PC보다 0.150초 빠름 · 오차 약 ±0.020초 |
| 서버 시계 · 확인 전 | 아직 사이트 시계를 읽지 않았다는 뜻. 예매 일정과 별개이며 오류가 아닙니다. | 서버 시계 확인을 누르면 측정 |

예매 시작 일정은 경기 목록의 일반예매 안내에서 읽으며 한국 시각으로 표시합니다. 읽지 못한 일정은 임의로 추정하지 않습니다. 서버 시계의 차이는 측정 당시 값이며 PC 시계를 변경하지 않습니다. 통신 시간이 있어 오차도 함께 표시합니다. 예매 서버 시계 조회에 실패하면 일반 웹 응답 시계를 대체 표시하지만 정시 클릭 예약에는 사용하지 않습니다.

- **버튼이 열리면 바로 클릭 (기본)**: 준비 화면의 실제 버튼 활성화를 감지해 한 번 클릭합니다.
- **서버 시계도 함께 사용 (시험)**: 확인한 예매 시작 시각을 기준으로 서버 시계 예약도 함께 준비합니다. 시작이 가까워지면 시계를 다시 읽습니다. 실제로 활성화된 버튼만 클릭하며, 활성화 감지와 예약 중 먼저 실행된 하나만 클릭합니다.

시험 방식은 목록에서 확인한 예매 시작 시각과 입력값이 일치할 때 사용합니다. 시각을 직접 수정했거나 준비 화면에서 바로 시작했거나 서버 시계 정보가 오래되면 기본 활성화 감지로 진행합니다. 예정 시각에도 버튼이 아직 비활성 상태라면 활성화를 기다립니다.

**진입 시각 보정(ms)**은 서버 시계 예약에 -250~+250ms를 더합니다. 기본값은 0이며 음수는 조금 이르게, 양수는 조금 늦게 확인합니다. 공식 판매 시작 시각을 바꾸지 않으며 활성화 감지는 계속 작동하므로 양수를 넣어도 이미 열린 버튼을 일부러 기다리지 않습니다. 음수를 넣어도 비활성 버튼을 강제로 활성화하지 않습니다. 통신 오차와 서버 허용 시점이 있으므로 음수가 더 빠른 입장을 보장하지 않습니다.

**진입 확인만 · 좌석 선택 전 정지**를 켜면 정상 진입 후 원스톱 좌석 화면 경로에 도착한 즉시 자동 진행을 끝냅니다. 도착 이후의 안내 확인·보안문자 제출·좌석 선택·선택 완료를 실행하지 않습니다. 실제 페이지 표시와 지원 여부를 먼저 검토할 때 사용하세요.

**새 Chrome 연결 방식의 실제 오픈 순간 속도는 아직 검증하지 않았습니다.** 기존 앱과 같은 성능이라는 결과나 서버 시계 시험 방식이 더 빠르다는 결과도 아직 없습니다. 버튼 활성화·서버의 허용 시점·대기열 처리·네트워크 상황은 별개의 단계입니다.

## 좌석 조건과 실패 처리

순위별 조건 묶음은 위에서부터 적용합니다. 같은 묶음 안의 구역·블럭은 동등한 허용 범위입니다.

| 순위 예시 | 구역 | 열 범위 | 통로 조건 |
|---|---|---|---|
| 1 | 실제 사이트에서 확인한 선호 구역들 | 1~5열 | 추정 통로에 접한 조합만 |
| 2 | 같은 구역들 | 6~10열 | 추정 통로에 접한 조합만 |
| 3 | 더 넓은 구역 범위 | 1~10열 | 통로 제한 없음 |

구역 이름은 사이트에 표시된 정확한 이름을 사용하세요. 빈 구역·블럭·열은 해당 항목 제한 없음입니다. 조건 묶음을 모두 끄면 기본 구역·블럭 순서를 사용합니다. 삼성 응원석이라고 이름만으로 가정하지 않고 해당 경기의 구역 안내를 확인해 설정합니다.

구장 설정은 실제 좌석 도면 데이터베이스가 아니라 독립된 선호 조건 보관함입니다. **예매 페이지에서 현재 구역 가져오기**는 예매 준비 페이지가 아닌 실제 좌석 페이지에 표시된 구역을 가져옵니다. 이 기능을 사용하지 않아도 구역·블록을 직접 입력하여 미리 저장할 수 있습니다. 라이온즈파크의 참고 구역 43개는 사용자 Drive의 2025년 자료이며, 현재 경기에서 확인된 목록이 아닙니다. 필요한 이름만 선택해서 조건에 추가하고 해당 경기 공식 안내와 대조하세요. 과거 블록·통로 가설은 자동으로 적용하지 않습니다.

- 연석은 표시 번호순뿐 아니라 확인된 물리적 배치와 인접 관계로 판단합니다.
- 통로는 행 끝·좌석 배치 간격에 따른 추정입니다. 실제 통로와 벽 쪽 끝자리를 항상 구분할 수는 없습니다.
- 시야방해석은 확인된 등급명 표시를 기준으로 제외하며 정보가 없다고 정상 좌석으로 가정하지 않습니다. 특별 묶음판매 좌석은 자동 선택하지 않습니다.
- 현재 확인한 지도 데이터 안에서 여러 후보를 계산합니다. 아직 불러오지 않은 구역의 좌석까지 확인했다고 취급하지 않습니다. 화면 목록은 400개까지만 표시하지만 후보 계산은 전체 확인 데이터를 사용합니다.
- 이미 선택된 좌석 등 명시적으로 확인한 선점 실패가 나오면, 도우미가 선택한 좌석을 정리한 뒤 다음 후보를 시도합니다. 20개는 처리 묶음 크기이며 종료 한도가 아닙니다. 다음 묶음도 최신 좌석 상태를 읽어 이어서 확인합니다.
- 모든 조건·구역을 확인해도 확보하지 못하면 다시 1순위부터 순환합니다. 전체 실행의 30분 제한은 제거했습니다. 사용자가 중지하거나 실제 선택 승인을 확인할 때까지 계속하되, 결과 불명확·연결 끊김·경기 변경처럼 안전하게 이어갈 수 없는 상황은 중지합니다.
- 실패한 동일 조합을 즉시 반복하지 않습니다. 한 바퀴를 돈 뒤에는 0.5→1→2→4→최대 5초 간격으로 새 순환을 준비합니다. 이 간격은 좌석 탐색 반복에만 적용되며, 오픈 순간의 진입 감지에는 추가하지 않습니다. 사이트에 갱신 수단이 없는 지도는 실제 좌석 변화가 보일 때까지 기다립니다.
- 처리 결과가 불확실하거나 로그인·인증·연결 문제가 생기면 중지하고 확인을 안내합니다. 선택 완료를 반복해서 보내지 않습니다.
- 자동 진행은 처음 지정한 탭과 그 탭에서 열린 예매창을 따릅니다. 실행 중에는 대상·조건 변경과 수동 좌석 조작을 잠급니다. 보안문자 입력과 중지는 사용할 수 있습니다.
- **중지**는 이미 서버로 보낸 요청을 취소하지 못합니다. 선택 완료 결과가 불확실하면 현재 선택을 보존하고 사이트 확인을 안내합니다.

마지막 작업 기록은 대기·직접 입력 시간을 포함합니다. 클릭 전달, 진입 요청·응답 관찰, 좌석 페이지 경로 확인을 구분하며 좌석 확보나 결제 완료와 같은 뜻이 아닙니다. 첫 중지 사유와 정제한 최근 결과는 `settings/last-run.json`에 보관하여 재실행 후에도 확인할 수 있습니다.

예매창이 재사용되면 현재 경기 탭에서 시작한 새 문서 전환인지 확인하여 이어받습니다. 진입 중 화면 전환으로 탭이 잠깐 목록에서 사라진 경우 최대 15초 동안 복귀를 기다리며 추가 진입 요청은 보내지 않습니다. 이 대기는 화면이 사라진 예외 상황에만 적용하며 정상 버튼 활성화에 지연을 추가하지 않습니다.

## 지원 범위와 보관 위치

현재 확인된 NOL 경기 카드·준비 화면·원스톱 좌석 화면 구조를 대상으로 합니다. 구장 설정을 저장할 수 있다는 사실이 해당 구장의 실시간 좌석 선택 검증을 뜻하지는 않습니다. 광주·잠실·라이온즈파크는 각 경기의 실제 좌석 페이지에서 추가 검증해야 합니다. 강원 FC 테스트 대상은 2026년 10월 18일 16:30 강원 FC–인천, 페이지에 표시된 장소는 강릉하이원아레나입니다. 이 경기 시작 시각을 예매 오픈 시각으로 사용하지 않습니다. 모든 종목과 구장의 좌석 화면을 지원하는 것은 아닙니다.

공식 좌석 안내 이미지는 구역 배치 참고자료입니다. 잔여석·실제 통로·연석을 확정하는 데이터로 사용하지 않습니다. 화면에 표시되는 정책은 해당 페이지를 마지막으로 읽은 시각 기준이며 다시 읽으면 갱신합니다. 과거 공지로 새로운 경기의 일정을 자동 설정하지 않습니다.

v0.9.4 설정은 실행 파일 옆 `settings/`에 저장하며, 구장별 조건은 `venue-profiles.json`에 보관합니다. 개발 실행은 `work/desktop-settings/`를 사용합니다. Chrome 로그인 정보는 Chrome이 관리합니다. 프로그램과 확장은 같은 PC의 로컬 연결을 사용하며 관련 예매 탭의 화면·좌석·처리 상태를 전달합니다. 인증 정보·서명·원문 네트워크 기록을 내보내거나 파일에 저장하는 용도로 만들지 않았습니다.

기존 일반 버튼/직접 전송 비교 도구는 개발용 `entry-comparison.cmd`로 남아 있습니다. 별도 Electron 비교창이므로 새 Chrome 설정 패널의 기능과 구분합니다. 새 패널은 일반 예매 흐름을 사용합니다.

직접 전송 비교 도구는 사이트가 정상적으로 만든 요청을 잡아 한 번 대신 전송하는 호환성 실험입니다. 버튼 전 준비 과정을 생략하지 않으며 더 빠르다는 검증 결과도 없습니다. 현재 Chrome 패널은 페이지 내부에서 활성화된 버튼에 즉시 이벤트를 전달하므로 마우스를 이동하는 자동화가 아닙니다. 서명된 진입 정보·대기열·입장 허가를 건너뛰지 않습니다.

## 개발과 검증

- `npm start`: Chrome 연결 패널 실행
- `npm test`: 기존 좌석·취소·복구·시각 로직 및 새 연결 관련 단위 검증
- `npm run package`: Windows 배포 폴더 생성

브라우저 확장·데스크톱 연결의 로컬 검증과 실제 Chrome 계정에서의 예매 검증은 다릅니다. 실제 오픈 시점의 진입 순위, 대기열 여부, 경쟁 중 좌석 확보는 별도 현장 검증이 필요합니다.
