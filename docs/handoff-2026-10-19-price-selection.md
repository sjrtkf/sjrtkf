# 가격 선택·우선순위·진입 검증 기록

기준: 2026-10-20 KST, v0.9.27. 작업 소스는 `F:\source`, 원격 저장소는 `https://github.com/sjrtkf/sjrtkf`다. 이 문서는 10월 19일 중단 당시의 미완성 지침을 현재 구현·관측 결과로 대체한다. 설치와 사용 방법은 [README](../README.md)를 따른다.

## 실제 로그에서 확인한 사항

2026-10-19 17:11:36 실행은 가격 조회 HTTP 200 뒤 `ADULT_PRICE_AMBIGUOUS`로 멈췄다. 당시 선택기는 가격명이 정규화 후 정확히 `예매가성인`인 항목만 허용했고 실제 가격명을 로그에 남기지 않았다. 이 제한은 v0.9.26에서 제거하고 가격 판단 로그를 추가했다.

2026-10-20 10:16 실행의 새 로그에서는 다음 가격을 직접 확인했다.

| 좌석 등급 | 가격명 | 금액 | 판단 |
|---|---|---:|---|
| 28 | 휠체어장애인+동반인 | 40,000원 | 별도 이용 자격·인증 조건으로 제외 |
| 28 | 휠체어장애인 | 20,000원 | 별도 이용 자격·인증 조건으로 제외 |

가격 조회는 성공했으며 좌석 선점은 0건이었다. 이번 중지는 `성인` 문구가 없어서 일반 가격을 놓친 결과가 아니다. **확인한 등급의 가격이 자격·인증 대상인 사실**과 **그 등급 때문에 전체 자동 탐색까지 끝난 동작**을 구분한다. 이 기록만으로 현재 경기 전체 등급의 가격을 모두 읽었다고 표현하지 않는다.

진입 로그에서는 목록 활성화 후 함수 실행 지연 약 0.3ms, 대기열 순번 1, 좌석 화면 도착이 관측됐다. 해당 실행은 기본 활성화 감지 방식이었으므로 서버 시각 예약의 실사이트 성공 근거로 사용하지 않는다. 관측된 지연은 클라이언트 계측이며 서버 내부 접수 시간과 다르다.

## v0.9.27의 동작

### 일반 가격 판단

`src/http-booking.js`의 `planStandardPrices(payload, seats)`는 좌석 등급별 요청 매수를 합산하고 가격 목록의 원래 순서대로 첫 적격 일반 가격을 선택한다. 특정 이름이나 최저가에 의존하지 않는다.

회원·추가 인증·카드·쿠폰·특별결제·할인·연령·이용 자격 조건을 확인한다. 금액, 좌석 등급 연결, 매수 상한과 잔여 수량, `L8003` 배수·`L8004` 최소·`L8005` 최대·`L8006` 고정 매수를 검증한다. 이미 선택한 가격은 덮어쓰지 않는다. 최종 `ValidatePricingSelection`과 사이트 화면 반영·다음 화면 도착 확인을 유지한다.

반환 값은 `{prices, assessment}`이며 실패에도 `error.priceAssessment`를 붙인다. HTTP 상태 요약은 판단 근거를 전달하고 `src/chrome-main.js`는 `price-selection`을 오류 처리 전에 기록한다. 진단에는 가격명·금액·등급·매수·원래 순서·선택·제외 사유만 남기며 인증 값이나 원본 응답 전체를 저장하지 않는다.

### 자격 가격뿐인 등급의 처리

자동으로 새 좌석 후보를 찾는 흐름에서 `STANDARD_PRICE_UNAVAILABLE`이며 **선점 0건**, 실패한 등급의 모든 가격에 자격·인증·할인 조건이 확인된 경우에는 해당 등급을 현재 회차에서 제외하고 나머지 후보를 찾는다. 다른 등급에 모아 둔 적격 좌석은 유지하며 설정한 조건 묶음과 전체 구역 대안 여부를 따른다. `seat-price-unavailable`에 제외 근거를 남긴다.

다음 탐색 회차에서는 `seat-search.resetSearch`가 `priceExcludedGrades`를 초기화해 가격 변경 가능성을 다시 확인한다. 현재 지도 대기 중 좌석 데이터가 바뀐 경우에도 다시 평가한다. 매수 부족만 있는 경우, 알 수 없는 가격 규칙·금액·등급 오류, 기존 선택 또는 가격 화면을 이어가는 경우에는 이 분기로 건너뛰지 않고 중지한다. 선점이 시작됐거나 결과가 불확실한 요청을 재전송하지 않는다.

### 좌석 조건과 우선순위

조건은 하나의 `preferences.json`에 저장한다. 사용자는 구역 이름·코드와 블록을 직접 입력하고 조건 묶음을 위에서부터 적용한다. 같은 묶음 안의 목록은 동등한 허용 범위이며 순서를 지정하려면 묶음을 나눈다. 코드 `1`과 `10`, 복합 블록 키 `001:1`과 `002:1`을 정확히 구분한다.

연석을 요구하지 않으면 여러 구역·등급·블록을 합산하되 높은 순위의 좌석 수를 먼저 최대화한다. 이번에는 합산 조합의 전체 점수가 같을 때 좌석 ID만 비교하여 다음 순위의 앞열 선호가 사라지던 부분을 수정했다. 개별 좌석의 앞열·통로 순위를 유지한다. 연석을 요구하면 서로 다른 블록을 합친 조합을 사용하지 않는다.

전체 구역 대안은 구역·블록·열 제한만 완화하며 매수·연석·시야방해석·장애인석 포함 여부는 유지한다. 화면은 이 조건 설정과 자동 진행에 집중하도록 정리했다. 제거한 보조 기능의 구현·자료·안내가 배포본에 남지 않는지도 검사한다.

### 서버 시각과 진입

기본 활성화 감지는 서버 시각 조회 없이 동작한다. 예약 방식은 최근 `ticket-server` 표본과 예약 시각 도달, 실제 버튼 활성화를 모두 요구한다. 60초가 지난 표본, 왕복 1초 초과, 허용 오차 초과 표본은 예약에 사용하지 않는다. HTTP Date 대체 표본은 표시용이며 예약에는 쓰지 않는다.

준비 화면에서도 시각이 만료되면 활성화만으로 진행하지 않고 새 표본을 기다리도록 수정했다. 재보정 전의 지연 타이머는 새 예약에 영향을 주지 않으며 만료 후 재보정을 허용한다. PC 벽시계 변경은 이미 연결한 단조 시계 예약을 바꾸지 않는다. 이미 좌석 화면에서 시작하면 시각 예약과 새 진입 요청을 만들지 않는다.

공식 서버 시각 API를 읽기 전용으로 조회하여 HTTP 200, 13자리 밀리초 시각 응답, 왕복 약 179ms, 예약 가능한 표본을 확인했다. 이는 실제 오픈 순간의 예약 진입·순번 개선을 검증한 결과가 아니다.

## 검증과 배포 확인

검사 개수와 최종 결과는 **v0.9.27 배포본의 `검증결과.json`**을 기준으로 한다. 이 문서에 이전 버전의 검사 수를 새 버전 결과로 옮기지 않는다.

필수 확인 범위:

- 실제 로그의 등급 28 가격 두 항목과 자격·인증 제외 사유 재현, 일반 이름에 `성인`이 없어도 선택, 표시 순서 유지.
- 자격 가격뿐인 등급은 선점 없이 제외하고 다음 적격 후보 탐색, 새 회차에서 재평가. 매수 부족·구조 오류·기존 선택은 무리하게 건너뛰지 않음.
- 구역·블록 정확 일치, 조건 묶음 순서, 분산 좌석의 여러 구역 합산과 앞열·통로 선호, 연석과 전체 구역 대안 제한.
- 기본 활성화·예약 방식 구분, 기한 전 실행 금지, 만료·재보정·PC 시계 변경·중지·문서 이동 및 중복 진입 방지.
- 화면에서 제거한 기능의 잔여 참조, 저장·재실행, 앱과 확장 버전 일치, 생성 확장과 패키지의 소스 일치.
- 목록→준비→안내→보안문자→좌석→가격→다음 화면의 격리 통합 흐름과 불명확한 결과의 중지 처리.

전체 단위 검사와 Electron 검사는 동시에 실행하지 않는다. 단위 검사 후 설정 화면, 목록·진입·안내, 통합 흐름과 입력 이벤트 없는 실행 검사를 수행한다. 필요한 검사 통과 후 패키징하고 `scripts/verify-package.cjs`로 소스·확장·OCR·결과 파일을 대조한다.

이번 확인에서 실제 사용자 브라우저의 좌석 선점·가격 승인·결제 성공은 검증하지 않았다. 사이트 구조가 달라지거나 새 조건이 나오면 정제된 실행 로그를 근거로 추가 판단한다. 현재 경기 전체 가격을 확인하려면 해당 세션의 각 등급 가격 응답이 필요하며 다른 경기의 과거 기록을 대신 사용하지 않는다.
