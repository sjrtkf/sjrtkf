## 실제 사이트에서 먼저 확인할 자료

1. 사용자가 열어 둔 예매 탭의 경기·회차·선택 좌석·좌석 등급을 읽기 전용으로 확인한다. 이미 선택한 가격이나 좌석이 있으면 보존한다.
2. 페이지 내부 가격 데이터 또는 공식 가격 응답에서 **전체 가격명과 응답 순서**를 가져온다. 가격 등급, 표시 이름, 정가·적용 금액, 매수 한도, 인증·회원·카드·쿠폰·자격 조건을 함께 확인한다. 로그용 표에는 인증 값·쿠키·세션·회원 식별값을 넣지 않는다.
3. 현재 코드의 공식 조회는 `/onestop/api/prices/{goodsCode}`이며 `placeCode`, `playSeq`, `bizCode`, `entMemberCode`, `seatType`, `seatGrade`를 사용한다. 필요한 세션 값은 페이지 안에서만 사용하고 외부로 복사하지 않는다. 로그인 정보를 추측하거나 브라우저 프로필에서 추출하지 않는다.
4. 도구가 실행되지 않으면 지원되는 다른 읽기 방법이나 저장된 자료를 확인한다. 실패한 도구를 근거 없이 반복하지 않는다. 과거 경기의 공개 응답과 현재 탭의 가격을 혼동하지 않는다.

로컬에 저장된 사이트 공개 코드의 조사 결과도 참고할 수 있다. `work/seat-public-code-v0.9.24/3995-61cf545912dc69ee.js`의 module `60032`는 `priceList` 응답 순서를 유지하며 이름은 `priceGradeName + " " + discountName`으로 표시한다. `PG002/PG004/PG007`은 가격 종류 배지를 생략하는 조건으로, 그 코드만으로 일반 가격임을 확정할 근거는 없다. 이름의 `장애|유공|보훈|재관람`은 별도 안내 대상이다. 이 파일은 로컬 조사 자료이며 GitHub에 포함하지 않는다.

## 남은 구현 순서

1. 실제 목록 확인 후 `planStandardPrices(payload, seats)`를 구현한다. 선택 좌석을 등급별로 합산하고, 해당 등급의 가격 목록을 원래 순서로 검사한다. 특정 `성인` 문자열 하나에 의존하지 않는다. 일반 가격으로 판단할 조건은 확인한 데이터와 구조를 근거로 정하고, 자격 가격을 단순히 첫 항목이라는 이유로 적용하지 않는다.
2. 회원·추가 인증·특정 카드·쿠폰·특별결제·할인·연령 또는 이용 자격 조건이 있는 행은 건너뛰고 다음 적격 행을 확인한다. 금액, 등급 연결, 매수 상한·잔여 수량 및 `L8003` 배수 / `L8004` 최소 / `L8005` 최대 / `L8006` 고정 매수를 검증한다. 한 등급이라도 적격 가격이 없으면 선점 전에 중지한다.
3. 계획한 반환 형식은 `{prices, assessment}`다. `prices`는 기존 `{selectedSeatCount, pgPrice}` 배열과 사이트 원본 가격 필드를 보존한다. `assessment.groups`의 각 항목은 `{seatGrade, seatCount, options, selectedIndex}`이고 `options`는 `{index, priceGrade, pgCode, priceGradeName, discountName, amount, eligible, reasons}`를 사용한다. 선택 실패 시에도 `error.priceAssessment`로 근거를 전달한다. 구현 시 이 계약과 테스트를 함께 확인한다.
4. HTTP 가격 단계와 상태·오류 요약을 새 함수에 연결한다. 일반 가격 없음의 예정 코드는 `STANDARD_PRICE_UNAVAILABLE`다. 응답 형식·등급 연결 오류는 구분한다. 기존 테스트의 `PRICE_REQUIRES_CERTIFICATION` 기대값도 새 정책에 맞춰 확정한다.
5. 선택된 좌석의 최종 가격 검증 `ValidatePricingSelection`과 사이트 화면 동기화는 유지한다. 가격 화면에서 재개, 좌석만 선택한 뒤 완료, 결과 불명일 때 재요청 금지, 수동 가격 선택 보존을 함께 확인한다.
6. 확장 빌드에 새 함수를 주입하고 생성 파일을 갱신한다. 앱·확장 버전과 최소 지원 버전을 맞춘 뒤 README를 실제 완료 상태로 갱신한다. 현재 화면 안내가 구현보다 앞서 있다는 점을 해소하기 전에는 배포하지 않는다.
