2026-10-16 조사 기록 · 가격 분석 제외

추가 조사, API 설명과 도우미 v0.9.6

예매 조건: 경기·구역은 가능한 일반 좌석에서 선택, 1매, 연석 불필요, 결제 직전까지. 잠실 3차전 인증은 완료했지만 보였던 1석이 사라져 실제 좌석 선택 완료와 결제 직전 도달은 아직 검증하지 못했습니다. DevTools 전체 패널 조사는 연결 기능 제한으로 미완료입니다.

1. 이번에 추가 확인한 사실

  • 5차전 진입 후 일반 등급 모두 0; 휠체어 등급만 잔여석 표시. 제한석은 선택하지 않음.
  • 3루 레드석 1 → 보안문자 인증 완료 후 0. 이후 조회에서는 모든 등급 0인 시점도 확인. 실시간 재고 보장 없음.
  • 잠실 초기 등급 31개, 회차 001, seatRenderType D2006. 광주와 같은 등급 코드라도 의미가 다릅니다.
  • 잠실 지도에 6,464개의 원과 6,464개의 사각형이 함께 있었습니다. 한 좌석의 표시·클릭 영역이 중복된 것이므로 합산하면 안 됩니다.
  • 이전 보고서의 전체보기는 복귀 버튼으로 취급하면 안 된다는 단정 수정: 잠실에서는 실제 등급 목록 복귀를 확인했다. 다만 모든 구장 동작을 일반화하지 않는다.
  • 투명 rect와 circle이 동일 좌석에 대응하므로 도형 개수는 별개 좌석 수가 아니다.

2. 삼성 라이온즈와 라이온즈파크

스포츠 메인 응답에서 수원삼성(축구, id78, bluewings)은 있으나 삼성 라이온즈가 아님. 현재 NOL 야구 코드의 존재 또는 부재 전체를 단정하지 않고 조사 응답 범위 내 미확인으로 기록.

현재 조사 자료에서 삼성 라이온즈의 NOL 팀 코드와 라이온즈파크 구장 코드는 확인하지 못했습니다. 미공개 코드가 없다는 뜻은 아닙니다. 다음 경기의 공식 카드 또는 정상 진입 후 초기 데이터에서 직접 확보해야 합니다. 기존 도우미에는 2025년 삼성 구역명 참고 목록이 있지만 현재 경기의 코드·재고 자료는 아닙니다.

3. 용어를 쉬운 말로 설명

필드·용어뜻과 주의할 해석
goodsCode 상품번호판매 상품을 식별합니다. 이번에는 차전마다 별도 상품번호가 있습니다. 경기 날짜나 팀 이름을 대신하여 요청 대상을 구분합니다.
placeCode 구장번호해당 상품에 연결된 장소 식별자입니다. 광주 26000514, 잠실 26001228을 실제 응답에서 확인했습니다. 연도·판매 상품에 관계없이 영구 고정이라고 단정하지 않습니다.
playSeq 회차번호상품 안의 공연·경기 회차입니다. 광주 1차전과 잠실 3차전 모두 001이므로 playSeq=001을 준플레이오프 1차전으로 해석하면 안 됩니다. 상품·구장·회차를 함께 사용해야 합니다.
reserved / reservedSeat지정석 운영 여부 등의 상품 설정입니다. true라고 해서 내 계정이 좌석을 예약했거나 선점했다는 뜻은 아닙니다. 성공 여부는 선택 응답과 다음 화면에서 확인합니다.
bookWait / bookWaitStatus취소표 등을 신청해 두는 예매대기 서비스 관련 설정입니다. 사람이 몰려 순서를 기다리는 접속 대기열과는 별개입니다. 현재 bookWait=false이고 공개 안내에도 예매대기 불가라고 표시되어 있습니다. NOTYET 하나만으로 미래 개방을 예측하지 않습니다.
초기 seats 배열처음 HTML을 만들 때 포함한 등급별 자료 목록입니다. 각 항목은 등급 코드·이름·초기 잔여석 등을 가지며, 이번 배열은 개별 의자 전체 목록이 아닙니다. 화면이 갱신되어도 초기 HTML의 값은 그대로 남을 수 있습니다.
SVG선을 확대해도 깨지지 않도록 도형과 좌표로 그리는 웹 그림 형식입니다. 이번 지도는 구역 그룹 g 안에 좌석 원 circle과 클릭 영역 rect를 함께 사용했습니다. 도형 개수를 좌석 수로 더하면 중복 계산됩니다.
seatInfoId개별 좌석의 서버 식별자입니다. 표시되는 좌석 번호와 같다고 가정하지 않습니다. 잠실 circle ID에서 상품:구장:회차:일련값 형태를 관찰했지만 다른 경기의 좌석 번호를 생성하는 근거로 사용하지 않습니다.
seatGrade / seatGradeName등급 코드 / 등급명입니다. 코드 19가 잠실에서는 3루 레드석이지만 광주에서는 다른 등급입니다. 구장 간 코드를 그대로 복사하면 안 됩니다.
blockKey / seatGroupIdblockKey는 구역 키이며 이번 지도에서 001:103 같은 값을 봤습니다. seatGroupId는 묶음 좌석 식별에 쓰일 수 있어 1석씩 자유롭게 살 수 있는지 별도 판단해야 합니다.
floor / rowNo / seatNo층 또는 위치 표기, 열 표기, 좌석 번호를 담는 필드입니다. 이름만으로 실제 모든 상품의 값 형식을 확정할 수는 없습니다.
rowIdx / colIdx / posLeft / posTop배치 순서와 화면상 위치에 쓰는 값입니다. 번호가 연속이어도 통로가 끼어 있을 수 있어 연석은 실제 배치·인접 정보를 함께 확인해야 합니다.
isSelectable / isExposable각각 선택 가능 여부와 노출 여부 관련 필드입니다. 그림이 보인다고 서버에서 확보 가능한 것은 아닙니다. 실시간 상태와 선택 결과를 추가 확인합니다.
isInterlocking / externalSeatMeta외부 좌석 시스템 연동과 그 메타데이터 경로에 관련된 값입니다. 광주·잠실의 관찰한 초기 설정은 isInterlocking=false였습니다. 모든 경기에서 같은 API가 쓰인다는 뜻은 아닙니다.
seatRenderType / miniMapYN지도 표현 방식 코드와 미니맵 사용 설정입니다. 잠실은 D2006을 관찰했지만 코드 명세 전체는 미확인입니다. miniMapYN=true만으로 모든 구역을 읽었다고 볼 수 없습니다.
bookingOpenTime서버가 상품 데이터로 제공하는 판매 시작 예정 시각입니다. PC 시간을 읽어 만든 일정이 아닙니다. 화면의 오픈 안내 표시 조건은 브라우저의 현재 시각과 비교하므로 PC 시계 오차가 표시 판단에 영향을 줄 수 있습니다. 서버의 실제 입장 허용·대기열 승인·네트워크 도착 시각은 별도로 작동합니다. 원문에는 시간대 접미사가 없고 국내 페이지 맥락에서 한국 시각으로 해석했습니다.
last-seat-modified좌석 상태 응답의 변경 시각을 읽는 헤더 이름으로 소스에서 확인했습니다. 이는 현재 PC 시각이나 해당 회원의 좌석 확보 증거와 다릅니다. 실제 값은 이번에 포착하지 못했습니다.

4. 확인한 API의 역할

API는 화면이 서버에 자료를 요청하거나 선택 결과를 전달하는 창구입니다. GET이라고 항상 읽기 전용인 것은 아니며 clear-select처럼 상태를 바꾸는 경로도 있습니다. 아래의 ‘소스 정의 확인’은 실제 해당 경기 요청·응답을 확보했다는 뜻이 아닙니다. 상대 경로는 클라이언트별 base URL과 결합됩니다.

5. 버튼 클릭과 직접 주소 진입

공식 목록의 예매하기 → /gates/partner(bc,gc,pc,cc) → 사이트가 발급한 대기열·입장 절차 → /onestop/seat

정확한 정상 진입 URL을 여는 것은 가능한 이동 방식이지만 주소만으로 필요한 세션·대기열·입장 허가가 생기지는 않음. /onestop/seat 주소만으로 새 경기를 지정할 수도 없음. 이번에는 직접 요청 재생이나 제한 우회를 실행하지 않음.

식당 비유로 말하면 주소는 접수 창구의 위치에 가깝습니다. 어느 창구를 찾아갔는지와 유효한 입장표·대기번호를 갖고 있는지는 별개의 문제입니다. 정상 주소를 여는 방식과 인증된 좌석 변경 요청을 임의로 재전송하는 방식도 다릅니다.

잠실 4차전 정상 버튼 진입 중 잘못된 접근 안내 후 목록으로 돌아옴. 원인 미확정. 잠실 3차전 정상 버튼 진입은 성공.

6. 예매 전 안내도와 실제 지도에서 유추할 수 있는 범위

가능한 비교확정할 수 없는 내용
구장·상품을 정확히 식별하고 같은 구장의 지도 범례와 실제 등급명을 대조광주·잠실 코드의 숫자 규칙으로 삼성 코드 생성
기존 예매 앱에서 공통 UI와 API 구조를 재사용할 가능성아직 공지되지 않은 삼성 상품번호·오픈 시각·회차 추정 확정

다른 구장의 등급 코드·좌표·좌석 번호를 삼성에 그대로 적용

안내도의 ‘3루 레드석’처럼 이름·범례를 실제 등급명과 대조할 수 있습니다. 그러나 예매 화면은 인원 묶음과 1루/3루를 더 세분화하므로 문자 유사도만으로 코드를 연결하지 않습니다. 처음 공개되는 경기는 새 기록 모드로 자료를 모은 뒤 구장별 조건을 추가할 수 있습니다.

9. 도우미 변경과 사용 방법

  • 보안문자 확인 후 기록·정지 모드
  • 현재 좌석 정보 기록 버튼
  • externalSeatMeta 관찰 경로 지원 (지원 스키마만 파싱)
  • 보이는 등급 목록 우선 처리·숨겨진 지도 제외
  • 선점 충돌 문구 확대 및 기존 다음 후보 처리 유지
  • 장애인·휠체어 제한석 기본 제외
  • 기존 v0.9.5 선호 설정 마이그레이션

새 chrome-extension과 v0.9.6 실행 파일을 함께 사용합니다. ‘4 시작’의 보안문자 확인 후 정보 기록하고 정지를 켜면 보안문자 직접 입력을 기다리고, 인증 화면이 사라진 뒤 자료를 저장하고 정지합니다. 이미 인증되었거나 문자가 없는 경우는 별도로 기록합니다. 기존 ‘진입 확인만’ 모드는 보안문자 처리 전에 정지합니다.

기록 위치는 실행 파일 옆 settings/observations입니다. 개발 실행은 work/desktop-settings/observations입니다. ‘현재 좌석 정보 기록’으로 나중에 새 구장의 정보를 추가 저장할 수 있습니다. 초기 배열과 현재 화면을 분리하며 회원·세션·토큰·쿠키·보안문자·가격은 기록하지 않습니다.

선점 충돌은 알려진 좌석 충돌 문구 또는 서버 오류 코드로 확인한 뒤 확인 버튼을 누르고, 도우미가 선택한 일부 좌석을 정리한 후 동순위의 다른 후보, 다음 순위 후보로 진행합니다. 같은 실패 조합을 즉시 반복하지 않으며 로그인 만료·알 수 없는 오류를 좌석 충돌로 간주하지 않습니다.
