# 후속 과제: 범용 좌석 표기와 예매 전후 정보 비교

기록일: 2026-10-20 KST. 기준 버전: **v0.9.30 / `a170b12`**.

사용자의 마지막 요청에 따라 다음 작업을 인계한다. **이 문서는 조사·구현 과제 등록이며, 아래 과제가 해결됐다는 보고가 아니다.** 이번 문서 업데이트에서 새로운 웹 조사, 좌석 선점, 결제 또는 프로그램 변경은 수행하지 않는다.

## 현재 완료 범위와 근거

- 예약 시각 진입: 준비 화면의 자동 요청도 문서 시작부터 보류하고, 설정 시각 **−2초~+2초 / 30ms 슬롯** 안에서 진입을 시도한다. 성공 응답을 사이트 함수에 넘겨 후속 흐름으로 연결한다. 지난 진입 구간으로 시작하면 중지한다. 상세 계약은 [진입 방식 문서](entry-strategy-2026-10-18.md)를 따른다.
- 축구 좌석: `WF구역 5열` 같은 원문에서 표시 블록과 열을 분리한다. 내부 블록 코드와 표시명을 함께 유지하고 확보 직전 다시 검증한다. WF 문자열 전용 처리는 아니며 WF·WG·W나 사례가 테스트에 있다.
- 구역·블록 입력: NFKC 정규화, 공백 제거, 대소문자 통일을 적용한다. 구역명·등급 코드는 정확히 비교하고, 블록은 코드·전체 키·표시명을 비교하며 `구역/블록/블럭` 접미사를 제거한다.
- 이전 배포 검증: 단위 검사 **860개**, 설정 화면 **72개**, 격리 Chromium 진입 **13개**, 예매 통합 **23개**가 통과했다. 수치는 로컬 `work/validation-v0.9.30.json`과 배포본 `검증결과.json`의 기존 결과이며 이번 문서 수정으로 재실행한 결과가 아니다.
- 실제 로그에서 축구 등급 `W1석(일반석)`, 표시 블록 `WF구역`, 내부 블록 코드 `004`와 열·좌석번호 형식을 확인했다. 격리 환경에서 해당 형식의 좌석→일반 가격→다음 화면을 검증했다. **실제 오픈 순간 성공이나 새로운 실사이트 좌석 확보·결제 완료는 검증하지 않았다.**

## 과제 1 — 특정 구장이나 W1·WF에 한정하지 않는 입력 처리

상태: **미완료. 현재 구현과 한계만 코드로 확인했다.**

요구사항은 어떤 문구를 넣어도 앱이 예외로 중단되거나 엉뚱한 좌석을 선택하지 않도록 하는 것이다. 모든 임의 문구가 실제 좌석을 유일하게 가리킨다고 가정하지 않는다. 해석할 수 있는 입력은 근거에 따라 연결하고, 나머지는 원인과 확인 가능한 후보를 보여준다.

현재 남은 한계:

- `W1`은 `W1석(일반석)`의 별칭으로 등록되어 있지 않다. 부분 문자열 일치로 해결하면 `W1`과 `W10` 같은 충돌이 생길 수 있다.
- 표시 블록 추출은 현재 `이름구역 + 공백 + 숫자/단일 대문자 + 열` 형식이다. 공백·하이픈이 포함된 블록명, 원문의 소문자, `WF블록 5열`, `AA열`, `A1열`, 복합 좌석번호를 일반 지원하지 않는다. 블록 코드 자체의 정확 일치와 원문에서 표시명을 추출하는 지원 범위를 구별해야 한다.
- 미일치 문구는 대체로 후보 0개가 된다. 기본 `fallbackAnywhere: true`이면 전체 구역 대안으로 넘어갈 수 있어, **입력 오인식·정보 부족·실제 매진**을 사용자에게 구별해 알려야 한다.
- 짧은 블록 코드가 서로 다른 전체 `blockKey`에서 반복될 수 있다. 같은 이름·번호가 다른 등급·층·경기장에 존재하는 경우도 검증해야 한다.

후속 구현:

1. 등급/구역 표시명, 별칭, 등급 코드, 블록 표시명, 짧은 코드, 전체 키, 층, 열·좌석 표시값을 각각 보존하는 정규화 모델을 만든다. 원문을 버리지 않는다.
2. 별칭은 출처와 적용 범위를 갖게 한다. 경기장·지도 버전·경기/회차·등급이 다른 매핑을 무조건 재사용하지 않는다. 정규화로 서로 다른 이름이 합쳐지면 모호함으로 처리한다.
3. 입력 결과를 `정확 일치 / 검증된 별칭 / 복수 후보 / 미지원 형식 / 확인된 목록에 없음 / 자료 부족`으로 구분한다. 불완전한 목록만 읽은 상태에서 “존재하지 않음”으로 단정하지 않는다.
4. 오입력이나 미지원 조건을 조용히 매진으로 취급하지 않는다. 전체 구역 대안은 기존 사용자 설정을 지키고, 전환 이유·해제되는 제한을 표시·기록한다.
5. 기존 우선순위, 열 범위, 매수, 연석, 여러 구역의 분산 좌석 합산, 시야방해석·장애인석 제외 조건을 보존한다. 모호한 별칭을 임의 선택하여 조건을 만족했다고 처리하지 않는다.
6. 진단에는 입력 원문·정규화 값·일치 방식·후보 수·불일치 이유·대안 전환 이유를 정제해 남긴다. 인증·개인정보나 원본 네트워크 응답 전체는 포함하지 않는다.

## 과제 2 — 예매 전 페이지와 예매 페이지의 정보 차이 조사

상태: **미조사. 아래는 조사 범위와 기록 형식이다.**

대상은 축구 W1/WF 사례를 시작점으로 삼되, **잠실 경기장 포스트시즌**, **광주기아챔피언스필드 포스트시즌**을 각각 조사한다. 같은 구장의 정규시즌·포스트시즌·주최 구단·경기별 명칭과 배치가 같은지도 확인한다. 부천 사례나 과거 경기의 내부 코드가 다른 행사에도 같다고 가정하지 않는다.

조사 후보 출처:

- NOL 티켓의 예매 전 상품·일정·좌석 안내 페이지와 공개적으로 제공되는 자료.
- KBO, K리그, 각 구단·경기장 공식 홈페이지의 좌석도·등급·가격 안내.
- 사용자가 제안한 **자리어때** 등 좌석 정보 서비스. 공식 자료와 대조하고 출처별 누락·상충을 기록한다.

위 출처 목록은 **자료가 존재한다고 확인한 목록이 아니다.** 후속 조사에서 정확한 URL, 확인일, 대상 경기·시즌과 자료 버전을 확보한다. 식별자와 배치 판단에는 공식 구단·경기장·예매처 원문을 우선하고, 다른 서비스 자료는 근거의 범위를 명시한다.

각 구장에 대해 아래 비교표를 실제 자료로 채운다.

| 필드 | 예매 전 공개 자료에서 확인할 값 | 예매 페이지에서 대조할 값 | 조사 시 판정 |
|---|---|---|---|
| 등급·구역 | 안내 이름, 등급, 색상, 가격 구분 | `seatGradeName`, `seatGrade` 및 실제 표시 | 같은 대상인지, 별칭·행사 차이인지 |
| 블록·층 | 지도 표시명, 블록 번호, 층·방향 | 전체 `blockKey`, 짧은 블록 코드, 표시명·층 | 일대일/일대다 연결, 이름 충돌 |
| 열 | 표시 열, 문자·숫자·복합 열 | `rowNo`, `rowIdx` | 표시 열과 물리적 행 인덱스의 차이 |
| 좌석 | 표시 번호, 결번, 묶음 좌석 | `seatNo`, `seatInfoId`, `colIdx`, 그룹 정보 | 표시 번호와 내부 식별자의 차이 |
| 배치·인접 관계 | 도면상 위치·통로·구역 경계 | 좌석 좌표/행·열, 인접 관계의 근거 | 이미지 추정과 확인 데이터 구분 |
| 잔여·제한·가격 | 공개된 안내와 갱신 시각 | 현재 잔여, 노출·묶음·자격·가격 조건 | 정적 안내와 실행 시 확인값 구분 |

실제 예매 데이터는 현재 코드가 읽는 `seatMeta`/`externalSeatMeta` 등 확인된 자료를 기준으로 삼되, 모든 구장이 같은 구조를 사용한다고 가정하지 않는다. 비교는 가능한 한 **같은 경기·회차·지도 버전**으로 한다. 시점이 다르거나 자료가 없으면 미확인으로 남긴다.

좌석 정보 비교에 필요한 읽기와 실제 좌석 선점·예매는 구별한다. 이 조사 과제의 자료 수집을 위해 선점하거나 결제할 필요는 없다.

## 과제 3 — 예매 전 공개 정보만으로 좌석 정보를 알아낼 수 있는가

상태: **미해결. 공개 자료만 사용하는 추출·매핑 기능은 아직 없다.**

현재 프로그램의 내부 좌석 ID, 전체 블록 키, 물리적 행·열과 인접 관계는 예매 페이지에서 얻은 메타데이터가 근거다. **표시 이름을 맞추는 일과 내부 ID를 알아내는 일은 별도 과제**로 다룬다.

후속 작업에서는 예매 페이지 데이터를 입력으로 주지 않는 추출 실험을 만들고 다음을 구분한다.

1. **직접 확인 가능:** 예매 전 공개 자료가 실제로 제공하는 등급·블록·열·번호·식별자. 값마다 출처와 적용 범위를 기록한다.
2. **근거를 갖춘 유도 가능:** 공개 도면이나 구조화 자료에서 검증 가능한 규칙으로 유도한 값. 추정 규칙과 오차·누락을 명시하고 별도 자료로 대조한다.
3. **판정 불가:** 공개 근거가 없는 불투명 내부 ID, 현재 잔여 상태, 세션에 종속된 값 등. 이름 유사성이나 숫자 규칙만으로 임의 생성하지 않는다.

공개 정보만으로 완전한 매핑이 안 되면, 어떤 필드가 부족한지와 예매 진입 후 최소한으로 읽어야 할 정보를 정리한다. **예매 전에는 선호 조건을 준비하고 진입 후 확인된 내부 식별자와 연결하는 대안**도 비교한다. 이를 “예매 페이지 없이 내부 정보까지 전부 알아냈다”라고 보고하지 않는다.

정적 지도에서 좌석이 그려져 있다는 사실을 현재 구매 가능한 잔여석으로 해석하지 않는다. 과거 예매 자료는 검증용으로 분리하며, 공개 정보만 사용하는 실험의 입력에 섞지 않는다.

## 다음 실행 순서와 완료 기준

1. 출처 목록을 조사하고 구장·행사별 비교표를 작성한다. 자료가 없는 구장도 결과와 추가로 필요한 자료를 남긴다.
2. 익명화한 실제 표기 사례를 수집하고 정규화·별칭·모호함 처리 규칙을 정한다.
3. 공개 정보만 이용한 추출 실험을 수행해 확인 가능/유도 가능/불가 필드를 판정한다.
4. 공통 입력·매핑 처리와 진단을 구현한다. 특정 구장명을 조건문에 추가하는 방식만으로 끝내지 않는다.
5. 아래 검사를 통과한 뒤 앱·확장을 함께 반영하고 배포한다. 실제 예매 검증 여부는 로컬 검증과 따로 기록한다.

완료 기준:

- 숫자·영문·한글·전각·공백·괄호·하이픈·접미사·잘못된 문구·빈 입력·긴 입력·복합 열/좌석번호를 처리해도 예외로 실행이 무너지지 않는다. 미지원은 명확히 표시한다.
- 등급 간 같은 블록명, 같은 짧은 코드, `1`/`10`, `W1`/`W10`, 정규화 충돌, 지도 버전 변경에서 잘못된 좌석을 선택하지 않는다.
- 미일치·자료 부족·매진을 구분하고, 설정한 우선순위와 전체 구역 대안 옵션을 보존한다.
- 축구 사례 외에 잠실·광주 포스트시즌 비교 결과가 각각 존재한다. 미확인 항목과 그 이유가 드러나야 하며 없는 자료를 추정값으로 채우지 않는다.
- 매핑마다 원문·출처·확인일·행사/지도 범위와 검증 상태를 추적할 수 있다. 오래되거나 충돌하는 매핑을 자동 확정하지 않는다.
- 공개 정보만 사용한 실험을 재현할 수 있고, 내부 ID나 현재 잔여를 확인하지 못한 한계를 명시한다.
- 기존 좌석 우선순위·분산/연석·가격 선택·중지 흐름과 **설정 시각 ±2초 / 30ms 진입 → 성공 후 예매 진행** 검사가 계속 통과한다.

사용자 설정·실행 로그·인증 자료는 GitHub에 올리지 않는다. 조사 결과와 재배포가 준비되면 이 문서의 각 상태를 근거와 함께 갱신한다.
